## 4. 核心 API 和输入前提

提供明确的公共函数，例如：

    normalize_workbook(workbook_path: Path, quality_report: dict) -> dict

它读取工作簿、返回内存中的标准化结果，不写回工作簿，不创建业务批次，也不代签批准。新测试驱动在函数完整成功后，才将结果另存到新测试目录。说明函数签名、返回结构及明确的阻断／运行错误类型。

质量报告由测试驱动调用真实 checker CLI，对当前测试输入重新生成；不得使用旧 checks、答案册或生成器内存数据作为质量结果。用 sys.executable、保留完整参数和实际退出码，每次 stdout／stderr 单独保存。

转换前必须核对：

- 报告为可用对象；复用只读接收器的 validate_report，结构缺失时明确阻断，不能靠 get 默认空对象继续。
- result=pass、issues 为空；四表全部存在，必需映射完整且不为 null；行数无隔离或结构阻断；完整勾稽为 ASSESSED 且相等检查为 true。只检查核心实际依赖的内容，不另造完整通用 schema 框架。
- 报告 workbook.sha256 与当前输入字节哈希相等，checker.sha256 与当前冻结 checker 相等。报告与另一个输入混用必须拒绝。
- 转换结束再核对输入哈希；读取失败、未知或变化均不能返回成功结果。

存在质量问题时，不转换“剩余好行”，不输出完整标准化数据。保留本次 checker 诊断报告并在测试结果中明确“未标准化”，不要把未产出的标准金额填零。报告结构或文件问题也应给出明确错误，不冒充零异常。

## 5. 固定转换口径

只处理四表固定字段，记录额外表／列但不擅自映射。使用实际表头和报告中的列位置，两者必须一致；不能假定字段永远在固定列号。

复用冻结 checker 的文本、日期及金额解析函数和字段定义，避免另造一套宽松解析。转换层仍须检查这些函数的错误返回，不能无视问题继续。需要适配接口时只在新模块中编写薄封装，不复制旧程序全部业务核验。

- 所有非空文本原样保留，不 strip、不转大小写、不合并名称、不猜补前导零。可空字段按已验收解析口径转为 None；文字 "NULL"、"N/A"、真正文本 "#N/A" 保持文本。Excel 错误类型不等同于文本。
- ap_date、payment_date 标准值为 YYYY-MM-DD 字符串。原生日期／午夜 datetime 可无损转换，带非零时间或带显式时间的文本不可自行截断。
- payable_amount、amount、allocated_amount 分别转换并改名为 payable_amount_cents、amount_cents、allocated_amount_cents，值必须为 Python int，且不是 bool。其余业务字段名保持不变。标准数据中不再保留同名的“元”业务字段，以免单位混用；原值保存在来源信息中。
- 使用已验收 Decimal 解析所得整数分，不通过 float 乘 100，不用 round 修复，不用浮点数累计。
- 保留全部资金状态、付款／退款关联、空或未知 ap_id 及收款对象差异。它们不是需要删除或修正的脏数据。退款金额仍为正数，资金方向由 transaction_type 决定。
- 不排序后重编号，不合并业务行，不补造主键或分摊。输出按原工作表业务行顺序，完全空白行另行记录其原 Excel 行号。

## 6. 结果和逐单元格来源结构

使用简单 JSON 可序列化字典，不引入框架。文档固定以下结构，具体内部小键名可选，但须清楚且前后一致：

- normalization_version：本次新版本，例如 TASK-004-normalized-1.0。
- mode=DEVELOPMENT_TEST_ONLY；明确未接入业务批次、未批准，不设置 next_step_allowed=true。
- source：输入路径、SHA-256、checker 版本哈希、规格哈希；路径只是附加信息，来源身份不能只用文件名。
- tables：四表各自的记录列表。每条记录包含 data（标准业务字段）、source（工作簿哈希、sheet、excel_row）和 cells（所有固定输入字段的单元格来源）。
- blank_rows：四表各自的空白行号列表。
- row_accounting：四表实际来源业务行数、标准化行数、隔离行数及空白行数，并与本次 checker 对照。
- amount_reconciliation：原报告金额、标准化金额、逐事件分摊及总体资金勾稽，单位统一为分。
- 接收报告记录的额外表／列及范围限制；不宣称真实性、全部业务完整性或 ERP 模板兼容性已验证。

每个 cells 项至少保留：输入字段名、实际列号和单元格坐标、Excel data_type、Python 值类型、读取到的原值及其编码方式、目标字段名和标准值。比如 payable_amount 的目标字段明确为 payable_amount_cents。

原值编码必须可解释：普通字符串原样，None 保留为空；date／datetime 以 ISO 字符串加类型记录；float 可用 repr 字符串加类型记录，不能冒称是 Excel 原始 XML 字面值或显示格式。需要时保留 number_format，但不能据它猜补 ID。JSON 禁止 NaN／Infinity；不能用 default=str 把所有类型不加区分地串化。

这里的“原值”是 openpyxl 解码值。原始 Excel 字节副本仍是权威原始载体，不用 JSON 声称能完整还原工作簿。每个测试输入副本必须留在测试容器，不覆盖已验收生成文件。

## 7. 转换勾稽

从标准化记录独立汇总，与当前 checker 报告对照，不直接把报告数字复制成“转换通过”：

1. 四表分别满足来源业务行数=标准化行数+隔离行数；成功结果隔离为零，且标准化行数与 checker 接受行数相等。空白行单列，不将四表相加称为资金笔数。
2. 三个金额字段按表独立求和，与报告的完整金额相等；付款和退款再按类型、状态分别核对数量及名义金额。
3. 每笔主表 amount_cents 等于其全部 allocated_amount_cents 之和，包括非结算记录和未匹配部分。
4. 已结算 PAY 主表总额=对应分摊总额；已结算 REFUND 同理。
5. 已结算主表净额=已知应付关联净额+缺失应付关联净额。缺失部分区分空 ap_id 和台账未找到，但都保留。结果与 checker 完整勾稽对照。

不要求应付总额等于付款总额，不将主表和分摊金额相加，不计算超付、重复足额、规则命中或损失。新层只核对转换是否丢行、丢金额或错用单位；完整业务质量核验继续由冻结 checker 承担。

任何转换／勾稽不一致都不能返回成功的完整结果；记录实际差异及来源，停止该输入，不自动修复。
