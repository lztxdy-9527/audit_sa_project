## 3. 已确定的架构约束

### 3.1 新运行层与旧开发链分开

为真实模式设计独立运行层/协议，不赋予开发控制器真实批准语义，不修改 0001—0008，也不规划在旧开发链上追加真实 0009。现有接收器和确定性计算核心可按冻结字节复用；其 DEVELOPMENT_TEST_ONLY/DEV_* 原始标记如实保留，新运行层另行说明其复用与边界，不能改标签冒充身份认证或职业审计保证。

本卡必须明确未来组件、候选 API、输入/返回、异常和状态转换表；所有候选名称标为“拟定、当前不存在”。Gate 决定记录、执行前提核验、实际标准化/装载成功是三件事，不用一个通用 next=true 混淆。

### 3.2 同一批次从开始固定共享运行绑定

Gate1/Gate2 从**同一个新批次的独立运行登记**取得共享 code/rules/config/input 六项，保持 P1 原形状和逐字段相等要求，不改冻结 P1/store。阶段材料集和 materials_fingerprint 可以不同，不能强求相等。

设计必须给出：共享 code.file_sha256 指向哪个实际单文件、完整代码清单有哪些当前存在文件、规则/配置/输入来源、独立读取和冻结时点、清单唯一排序与 canonical 算法、文件 SHA 与对象指纹的不同含义。不得用“放空/暂填/后面补齐/取当前适配器”留下实施歧义。

未来实现时，在第一次 Gate1 请求前把该运行版本启用的全部相关组件纳入登记；新增或变更组件后是新运行版本/新批次，不能补进旧登记复用旧批准。尚不存在的候选文件只能列为未来构成要求，不能本卡编造其真实 SHA 或创建占位文件。阶段自有组件也须绑定到批次代码清单，不能因共享摘要而漏掉实际执行者。

当前 TASK-024 的 32项/14项请求与保存协议保留。若新运行层需要新的 Gate1 请求/封套版本，明确新增或版本化的兼容边界和后续授权修改位置；旧事件只读保留，不转换、补签、追认或更换绑定。不能假设现有独立记录天然已经批准一套尚不存在的新运行代码。

### 3.3 Gate1 → 标准化/入库 → Gate2 候审

拟定顺序必须为：接收并核验来源 → 固定批次运行登记 → 展示 Gate1 材料并保存人类决定 → 实读核验当批有效 Gate1 APPROVE 与当前材料/版本 → 标准化与 SQLite 装载/核验 → 固定 Gate2 材料请求 → 暂停。

HOLD/REJECT 可以保存但不得执行。质量/结构阻断、失败诊断、锁、缺凭证、错批/错指纹/错版本、材料变化或不完整历史不得被 APPROVE 掩盖。有效 APPROVE 的核验是某一具体动作的必要前提，不把“存储已成功”直接解释为所有后续权限开放。历史限定 scope 的能力边界保持，不凭目录之外不存在已知记录推断全局完备。

只读检查点/状态恢复不调用标准化、装载或重新保存决定。失败只在新的运行输出目录留诊断，保留已提交/半写现场，不能因失败自动换批次或 scope 重试。

### 3.4 复用核心的实际接口与路径

只读确认 `normalize_demo_data.normalize_workbook(workbook_path, quality_report)` 和 `store_demo_sqlite.load_normalized_to_sqlite(normalized, database_path)` 的现行契约、输入要求与 I/O 边界；不得凭印象写候选接口。

SQLite 核心当前只接受 `data/sqlite_tests/` 下新文件，返回 `DEV_SQLITE_VERIFIED`。设计应在这项既有允许范围下为新运行使用独立新子目录，另用新运行封套关联；本卡不扩大核心路径权限、不改核心状态或内嵌旧引用。标准化输出/装载核验报告/数据库分别登记确切文件 SHA 与必要对象指纹；不复制开发态已批准工作流来绕开真实 Gate1。

Gate2 候审材料明确包含批准前已经可得的标准化产物、数据库及装载/质量/勾稽证据，须实读数据库与对应报告核对；不要求筛查、复算、事实底稿或初判已经运行。Gate2 请求准备与 Gate2 决定保存/规则执行分阶段验收。

### 3.5 确切协议与末端规则

对拟定持久产物和 API 给出封闭字段/严格类型/常量/来源/相等关系，完整对象与文件字节分别绑定；所有摘要算法明确唯一正文，若有自指字段须明确排除，不能留“实现任选”。不承诺本地哈希可抵御同权限全面重写。

独占写新目录/新文件；有效 failure 优先阻断；协议拒绝与 I/O/运行失败分开并保留 cause/context。全部必要语义消费之后执行一次完整有界字节/集合/路径确认，之后不再读取候选决定成功；以初始同缓冲或本次 writer 的预期核对。定义最后成功提交点及失败元数据，避免自指、重复写成功载荷与审核失败不支配出口。

人类姓名/身份声明/事件ID/时间/决定/原因仅来自显式提交，程序不得生成或预填。契约生效时间沿用原文登记，不用未来 Gate 时间规则追溯拒绝 V1。初判/AI/终判仍未开放；本卡不设计其新增接口。
