### 3.2 固定规模与组成

主演示工作簿必须恰有：suppliers 20 行、payables 993 行、payments 1000 行、allocations 1005 行，均不含表头。1000 指资金事件行数，包含退款和非结算记录，不是四表合计。

组成固定如下，每一组与其他组使用独立应付及资金事件，不能意外共享应付键造成额外命中：

1. 普通一次付款 963 组：每组一张应付、一笔足额付款、一条分摊。
2. 正常分期付款 5 组：每组应付 5000.00，分付 2000.00、3000.00，共 10 笔付款、10 条分摊。
3. 正常合并付款 5 组：每组一笔 10000.00，分至两张应付 6000.00、4000.00，共 5 笔付款、10 条分摊。
4. 全额退回其中一次重复付款 1 组：按 C06，2 笔 PAY、1 笔 REFUND、1 张应付、3 条分摊。
5. 正常部分退款 1 组：应付 5000.00，支付 5000.00、退回 2000.00，净付 3000.00；1 张应付、2 个事件、2 条分摊，不命中四规则。
6. 非结算付款 3 组：PENDING、FAILED、VOIDED 各一笔，各有独立应付及分摊。
7. 尚未付款 3 张应付：无资金事件和分摊。
8. 预埋当前规则线索 9 组：见下一节，共 14 个已结算 PAY、7 张应付、14 条分摊。

因此资金事件为 963+10+5+3+2+3+14=1000；应付为 963+5+10+1+1+3+3+7=993；分摊为 963+10+10+3+2+3+14=1005。已结算 PAY 995 笔、已结算 REFUND 2 笔，另有非结算 PAY 3 笔。

普通组金额采用整数分生成，再格式化为两位小数文本；至少包含 0.01 和 1234.56。其他普通金额可在 100.00 至 5000.00 间按种子生成。至少两张普通应付使用相同展示单号、不同供应商和不同 ap_id，用于证明关联不依赖展示编号。

供应商名称用虚构中文名，供应商 ID 使用有前导零的文本。主数据和事件 ID 使用普通编号，不用 DUP、OVERPAY、ABNORMAL、CASE 等暴露答案的前缀。所有引用一致，日期在九月内，退款不早于付款。主表各金额和分摊金额必须精确相等，主演示文件不能混入阻断性质量错误。

第一版正常金额以两位小数文本写入，日期以 ISO 文本写入，ID 真实单元格类型为文本，空值写为真正空单元格。这样不依赖 Excel 浮点金额求和，也不伪造不规范 ERP 数据。故意非法的单元格只出现在对应负向 fixture。

### 3.3 九组预埋线索及独立答案

- 3 组现存重复足额：每组应付 5000.00，两笔不同流水各支付 5000.00；每组 R01、R02 各一条。
- 2 组只超额：每组应付 5000.00，支付 3000.00、2500.00；每组仅 R02 一条，超额 500.00。
- 2 组缺失应付关联：各付款 5000.00，一组 ap_id 为空，一组填不存在标识；各 R03 一条，不创建对应应付。
- 2 组收款对象不同：各应付 5000.00、付款 5000.00，收款 ID 与应付供应商 ID 不同且两者均存在主数据；各 R04 一条，不预设实际违规。

主文件预期共 12 条规则命中：R01=3、R02=5、R03=2、R04=2。R02 按唯一应付汇总的预期超额为 16000.00 元。九组场景、十二条命中和超额金额是不同统计口径，不能互相替代或相加称作损失。

生成时通过“正在构造哪种已知场景”的登记信息建立答案，不调用检测规则推导答案，也不把未来 SQL 或 Python 检测函数导入生成器。未命中这些规则不等于所有业务已经证明正常。

答案册至少记录：版本、合成声明、种子、主输入 SHA-256、预期命中计数，以及每条预期的 rule_id、结构化命中键、相关应付／付款／分摊／退款 ID、预期整数分金额、理由及实际工作表行号。R01 键为 ap_id+payee_supplier_id，R02 为 ap_id，R03/R04 为 allocation_id。说明四规则范围内不应命中的分期、合并、退款、非结算和相同展示单号场景。

JSON 与 Markdown 来自同一登记内容；Markdown 是方便人读的答案说明。答案只用于开发验证，不能作为初步人类判断界面的预填内容。本任务不生成 AI 审计意见或最终审计判断。

### 3.4 可重复性

相同种子应生成相同四表记录、顺序和逻辑答案。业务内容指纹取重新读取后的四表表头及有序行内容，使用固定 JSON 序列化、UTF-8、SHA-256；不得用 Python 内置 hash()。

XLSX 是 ZIP 容器，字节及文件 SHA-256 可以受元数据影响，不要求字节级相同。比较答案时排除文件 SHA-256 等运行来源字段，比较实际预期键、金额和理由；来源信息仍要分别准确保存，不伪造相同文件哈希。

## 4. 小型验收工作簿与校验脚本

### 4.1 22 个 fixture

按规格第 6 节逐条忠实展开共同默认值，不从主文件随机抽样替代手工案例：

- C01—C13 各一份，共 13 份。
- C06b、C07b、C09b、C10b 各一份，共 4 份。

### 4.2 只做数据质量校验

`check_demo_data.py` 接受 `--workbook` 和 `--report`，从实际落盘 Excel 重新读取原值与类型，而不是校验生成器内存中的列表。报告路径必须为新文件，不能覆盖输入。退出码：0=数据质量检查通过；1=发现数据质量／范围问题；2=参数、路径或文件无法读取等运行问题。

允许空或未知 ap_id，以及已知收款对象与应付供应商不同；这不能让质量检查失败。检查器不实现 R01—R04，不输出命中计数或审计等级，不读取答案册来决定是否通过，也不导入生成器的造数／判断函数。
