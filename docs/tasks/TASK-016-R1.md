## 2. B1：指纹必须完整匹配，不接受尾随LF

当前`_HEX64 = ^[0-9a-f]{64}$`配合match，允许在64位十六进制后带一个LF。GPT分别在四项source指纹追加LF，用实际变更后的packet计算匹配的expected/submission指纹，公开API全部返回VALIDATED并把65字符来源指纹复制进record。

修复共同校验，使每项指纹**恰为64位小写十六进制字符串**，整个字符串完整匹配。不得通过strip、截断、转小写或忽略后缀把非法来源悄悄修成合法输入；应InitialJudgmentBlocked，field准确指向对应来源字段，不返回成功record。

覆盖四项来源、expected_packet_sha256、submission.fact_packet_sha256共用的格式检查。合法输入的协议版本、返回内容、来源绑定和所有null/false边界保持不变，不借机重构、改时间口径或扩大身份能力。

本问题是字符串协议校验，不要求核心防止调用方同时重声明全部指纹。反例中的packet外层指纹必须与候选对象一致，才能准确证明拒绝的是非法来源格式，不能靠旧expected指纹不匹配提前拒绝来冒充关闭。
