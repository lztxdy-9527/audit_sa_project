## 2. 勾对规则（交易级，确定性）

匹配优先级：
1. **引用优先**：付款/退款的 `bank_reference`（或索引声明的 `bank_txn_id`）== 流水的 `reference`/`bank_txn_id`；
2. **无引用时**按 `金额（整数分）+ 日期 + 对方户名` 精确三元组匹配；
3. 同一流水只能匹配一条账务记录，同一账务记录只能匹配一条流水；重复即 `DUPLICATE_*`。

核对内容：金额精确相等、日期相等（差异记为日期不符/未达）、收付方向（付款 OUT、退款 IN）、对方户名/账号、期间（≤2026-09-30）、币种。

分类枚举：`MATCHED`、`AMOUNT_MISMATCH`、`DATE_MISMATCH`、`COUNTERPARTY_MISMATCH`、`DIRECTION_MISMATCH`、`REFERENCE_CONFLICT`（引用指向的流水金额/日期/对方与账务不一致）、`DUPLICATE_BANK_LINE`、`DUPLICATE_MATCH`、`LEDGER_UNMATCHED`（账有实无）、`BANK_UNMATCHED`（实有账无，即未达账项候选）。

期间合计（仅交易级）：`OUT` 合计 == 已结算付款合计；`IN` 合计 == 有效退款合计；差异单列。若流水提供期初/期末余额，仅做算术自洽（期初 + IN − OUT = 期末），**不**与账面银行存款科目余额相比（需报表层输入，另行授权）。

## 3. 输出与底稿

`bank_reconcile_report.json` + `.md`：
- 逐条匹配状态与依据（引用匹配/三元组匹配）；
- 差异清单（账务 ID、流水 ID、字段、实际、预期、分类）；
- 未达账项清单两侧分列（账有实无 / 实有账无），并注明“未达账项≠差错，需人类核查”；
- 现金/资金口径提示：整笔付款金额是资金口径，与分摊金额分别列示，不相加；
- **人类核对结论列留空**（不采集、不虚构）。

## 4. 测试与证据

- 正常：付款/退款与流水全部匹配（引用或三元组），期间合计一致，未达账项为空。

- 每例保留命令、stdout/stderr、退出码、报告；原输入与既有证据不改。
