## 3. F01：把所有提交前核对放回同一事务

当前代码顺序是写入 → COMMIT → verify_database。改为：建空 schema → BEGIN → 写入业务／来源／元数据 → 从当前连接读取并独立核对 → COMMIT → 关闭 → 无覆盖发布 → 最终哈希 → 返回成功。

- 所有业务、来源和运行元数据在同一个数据事务中；事务内不得使用会误提交的 executescript。
- 数量、金额、分组、逐笔分摊、净额、外键、完整性、往返及第 6 节元数据核验全部通过后才提交。SQLite 允许本连接读取本事务未提交的记录，不需要先提交才能核对。
- 提交前失败时，根据实际事务状态回滚。保留空 schema 暂存库，六张表数据行数均为 0，且无成功报告、无最终目标库。不能只清空部分表，也不能删除失败现场冒充回滚。
- 自关联仍需可延迟，不以改变原 Excel 行顺序规避。真实空付款正例仍应通过。
- 约束／核对错误都要有阶段、目标和暂存路径、具体差异；有底层异常时保留原因。回滚或关闭再次失败时不要掩盖最初错误。
- 不再把异常类型统一解释成“数据已回滚”。提交后关闭／发布／最终哈希失败，须保留真实现场、说明阶段与已发生的提交／文件状态，不虚报六表零行或文件不存在。这不要求建立正式审批状态机。
