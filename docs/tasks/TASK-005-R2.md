## 3. 唯一修复点与明确行为

当前 `_cleanup()` 捕获关闭的 sqlite3.Error 后仅记录 close_notes，再无条件清空 connection。正常流程也使用它，导致关闭出错后继续 hash_staging／publish_database／final_hash，最终返回 DEV_SQLITE_VERIFIED。

将正常关闭与已有错误后的尽力清理分开处理，具体结构由执行端选择：

- **正常路径**：关闭必须成功。关闭抛异常时，立即中止成功流程，按 `阶段=close_database` 抛 SqliteLoadError，保留目标／暂存路径及原异常链。不得继续哈希或发布，不返回成功报告。
- 关闭错误发生在 COMMIT 之后，因此说明 `数据事务已提交=True`、`目标文件已发布=False`，保留已提交暂存库和实际行数，不假报回滚或六表零行。
- 正常关闭报错后，即便错误清理再次尝试关闭并成功，也不能把本次调用恢复成发布成功；本次错误应如实交给调用方。
- **已有错误后的清理**：尽力关闭；清理关闭再失败只作为附记，不能覆盖最初的核对／写入／文件错误。不要为了隐藏关闭失败而丢弃仍需清理的连接引用。
- 不需要无限重试或资源回收框架，只要正常关闭错误不会被成功流程忽略，错误清理不会掩盖原错误即可。
