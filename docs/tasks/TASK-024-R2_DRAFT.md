### 4.2 函数代码稳定与输入不变性分开

可以保留 function code fingerprint 作为代码观察，但字段/检查/回执要明确它只测函数代码，不能称“消费对象引用不变”。真正不变性要求：在进入真实核心/公开存储或准备调用之前，保留实际消费对象引用并取得规范指纹与**独立深拷贝的完整输入快照**；返回或异常后、所属 API 收尾再对同一引用计算指纹。路径型输入保存实际可得文件现场及范围，不能只用 str(path) 代表文件未变。

不得在 describe_input 的 value 中留下原输入别名，也不得只做两次调用后值比较。输入/返回描述中的 byte_size/SHA 必须与保存的完整 value 自洽；输出也独立快照，不能因后续使用同一返回对象而改变“当时返回”。真实异常保留完整 traceback/cause/field/stage，不再调用一次核心凑对照。

最小控制：实际冻结 P1 正常调用输入三时点相等、完整真实返回与落盘相等；只在测试 wrapper 中先调用真实 P1 再故意改内存 submission.reason（或其他明确字段），观察器必须检测对象改变、保留原前快照且不把函数代码未变称 PASS。该项明确是观察器辨识度故障，不声称冻结核心会改输入，不改业务文件。
