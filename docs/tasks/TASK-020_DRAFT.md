## 4. 协议正文必须定清的内容

首部标注`PROTOCOL_DESIGN_DRAFT_NOT_IMPLEMENTED`。范围仅为独立纯内存的**Gate决定记录校验与构建**；Gate1、Gate2分别列出材料和关系，持久化/恢复/控制器/宿主接线均留后卡。本卡不设计真实初判记录结构，D3只登记为P3约束；不设计AI或终判。

协议应给出一个具体可审阅的拟定公开函数签名和严格JSON字段集合（必需/可选/未知字段处理、类型、允许值、指纹含义、输出/异常），后续纯核心任务可以据此实施。允许决定技术字段名；不得引入新的业务范围、重要性/缺陷等级或认证承诺。至少明确：

1. **原始提交**：event_id、batch_id、gate、对应请求标识/材料绑定、APPROVE/HOLD/REJECT、提交人显式身份声明、决定时间及说明，均由调用方明确提供。非空字符串不裁剪/改大小写/转数字；前导零与人类字符串原文保留。不能自动生成事件ID、姓名、时间、批准或默认决定。
2. **五项义务**：主理人的明确决定、批次标识、守门材料指纹、时间及说明缺一不可。时间格式及有效日期/时区的校验规则作为拟定协议写清，不补当前时间/时区，不把整理时间当人类决定时间。
3. **材料与契约**：给出每处Gate所需材料封装的确定形状、完整性/阻断/失败状态、运行代码/规则/配置/输入绑定；正式契约版本与确切文件SHA须独立绑定，不接受候选/草案状态冒充正式契约。材料集本身的规范对象指纹与内部各文件字节SHA分别命名、分别核对；不得以重新计算外层指纹掩盖内层关系不符。
4. **预期绑定来源**：拟定API应有调用方已核验的独立预期值，不能只把submission或materials里的自报指纹与自身比较。说明纯内存核心能验证哪些对象关系、哪些磁盘实读/契约生效/来源完整性事实只能由未来适配层负责；核心不认证人类身份或证明业务真实性。
5. **Gate顺序**：Gate1针对接收/范围/结构，Gate2针对标准化/入库/勾稽。Gate2须绑定同批次已核验的真实Gate1批准及当前材料/运行版本；不能仅凭一个APPROVE字符串、开发态phase、模拟凭证或本次D2总体建设许可放行。真实Gate1/Gate2在后续接入时分开验收。
6. **决定与放行分开**：合法HOLD/REJECT可以形成决定记录，但不得允许继续。完整核验材料报告存在结构/质量阻断时，APPROVE必须被拒绝；不得删问题或只算残余子集。材料失败/凭证不完整/错批次/错指纹/版本变化不能返回成功记录。记录内存校验成立不等于已保存、已批准执行或已产生真实人类判断。
7. **历史与重复事件**：决定一经保存不可覆盖；变化新批次、不复用旧决定。拟定纯内存核心若校验重复事件/前序决定，必须显式接收必要历史快照并写清能力边界，不能宣称无状态函数能发现磁盘或全局全部重复事件。
8. **身份边界**：真实人类输入使用独立于SIMULATED_HUMAN/SIMULATED_TEST_ONLY的显式声明；拒绝模拟身份/记录/开发态凭证冒充，拒绝AI/SYSTEM代签。声明不是强认证，不声称识别文本是否真由人类独立完成。
9. **确定性与异常**：规范JSON沿用UTF-8/ensure_ascii=False/sort_keys=True/separators=(",",":")/allow_nan=False，输出记录不内嵌自身指纹；返回深拷贝、无别名、不改输入。同输入同结果，不读写文件/库/网络、不导入宿主/控制器/上游/测试/答案册，不产生状态迁移。协议/绑定错误给可定位字段与原因；意外内部异常保留cause，不包装成功。
10. **停止点**：纯核心只返回内存校验结果；无CLI/持久化/恢复接口，不设置gate1_approval/gate2_approval、next或AI权限，不保存真实初判。拟定后续宿主持久保存和运行放行须独立验收，不能将纯核心VALIDATED等同RECORDED/APPROVED。

哈希字段必须完整64位小写十六进制匹配，尾LF/CRLF/空格/大写拒绝；普通身份ID或批次ID即使形状像64位哈希也仍是合法字符串，不得套用“不是哈希”的排除。
