## 4. B3：quality状态与决定记录接受矩阵冲突

§9允许HOLD/REJECT形成记录，又无条件拒绝quality.status为BLOCKED/FAILED；C-58则要求有quality_blockers的HOLD成功。若把BLOCKED理解为存在质量阻断，HOLD会被拒；若为了让C-58成功而保留status=OK，则造成OK与非空阻断列表矛盾。协议没有选择唯一解释。

须区分“完整核验材料显示存在阻断”和“材料/核验过程失败或凭证不完整”。前者应能保存HOLD/REJECT的内存决定记录且固定不放行，APPROVE拒绝；后者不成功。明确OK/BLOCKED/FAILED与阻断列表的一致性、全部三种决定的结果和最早定位字段，并同步C-54—C-58及记录形状。不得靠留下矛盾的OK状态使HOLD通过。§2.2的“无放行字段”与实际execution_allowed=false边界字段也应统一措辞。
