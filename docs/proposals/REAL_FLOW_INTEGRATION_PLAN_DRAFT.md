## 1. 阶段划分（全部为候选步骤）

分阶段实施的前提是 D1/D2 获**明确采纳**；任何阶段都不得一次重写全部宿主/控制器。

### P0 —— 前置确认（人类动作，非实现）

- **前提**：D1（契约内容与生效方式）与 D2（真实决策保存模式许可）明确作出。
- **拟新增组件**：无。
- **输入/输出**：输入为人类决定；输出为**已生效**的正式契约版本与指纹、以及明确的决策协议（哪些字段、谁提交、如何绑定）。
- **绑定不变量**：正式契约版本/指纹一经确定即写入后续批次登记；协议变更同样须新版本。
- **停止点**：D1/D2 任一未决或附条件未满足 → 停在 P0，不进入 P1。
- **最小验收（负向为主）**：无生效契约指纹时，P1 不得启动；把候选稿文本当作已生效契约即判为失败。

### P1 —— 真实决策记录纯核心（新建，独立于宿主）

- **前提**：P0 完成；确定决策记录协议与候选字段。
- **拟新增组件**：一个**独立纯核心**脚本（建议名 `build_demo_decision_record.py`，**设计建议、当前不存在**），提供纯函数：`build_decision_record(batch_id, materials, submission, *, expected_*_sha256) -> {"record","record_sha256"}`；提交与记录均显式声明身份来源。
- **输入/输出/绑定不变量**：输入为人类**明确提供**的提交对象（决定内容按原文）+ 当批材料指纹；输出为规范 JSON 记录 + 规范指纹。**保存程序只校验并按原文记录，不生成、不补造、不推断批准或判断**。
- **指纹口径（澄清，纠正过度概括）**：本方案区分两类 64 位小写十六进制值，**二者计算对象不同、字段含义不同、不互相替代**：
  - **文件 SHA-256**：取自**确切原始字节**——包括工作簿、数据库、Markdown/契约文件以及 JSON 文件；同一对象若以不同排版/换行保存为两个 JSON 文件，其文件 SHA 也可能不同。
  - **规范 JSON 对象指纹**：仅取自**约定的 canonical JSON 字节**（如既有已验收体系中的 `packet_sha256`、`record_sha256`）。
  因此不得把"批内所有指纹"一律说成以 canonical JSON 计算，也不得用对象指纹替代文件字节哈希（或反之）。
- **输入保真口径（澄清）**：P1 的入口是**内存中的提交对象**，它能按原文保存**人类字符串字段与接收到的对象快照**；但确定性序列化**不等于**保存了原始 JSON 文件的排版/换行/BOM 字节，因此**不能承诺"JSON 不重排"式的原始文件保真**。若后续设计**文件输入**并要求原始提交保真，则须**另存该次确切文件字节/文件 SHA**，并与解析对象的规范指纹**分别绑定**。本轮只澄清候选接口边界：**不选定、不设计、不实施**新的 I/O 接口，也不修改任何现有实现。
- **停止点**：出现缺决定、错批次、错指纹、材料变化、重复事件、模拟身份冒充、未解决质量阻断、失败现场或不完整凭证 → 记录具体问题并停止，不产生"通过"记录。
- **最小正负向验收**：正向——合法提交产生记录且规范指纹可复算；负向——上列每一类拒绝条件各至少一例被拒且给出可定位原因；拒绝不得靠默认值放行。

### P2 —— 独立保存/恢复 + 守门点接入（Gate 1 / Gate 2 分开验收）

- **前提**：P1 通过；契约版本与决策协议已登记。
- **拟新增组件**：真实决策记录的**独占保存/读回/恢复**步骤（拒绝覆盖既有文件；失败只在新输出目录留失败诊断）；宿主侧**最小**接线，把真实决定接到 Gate 1、Gate 2 的暂停点。**真实 Gate 1 与 Gate 2 分开验收**，不与 P3 合并。
- **输入/输出/绑定不变量**：每个真实决定绑定**本批次**标识 + 提交时核验的材料指纹 + 提交人显式声明 + 时间 + 原因；其中"时间"与"原因／决定说明"须来自**人类明确提供**的输入（程序不生成、不推断，见候选契约 §3.1／§3.2／§3.3 的五项记录要素）。人类提供的**字符串字段按原文保存、不改写**；所指材料指纹的口径与 P1 一致（文件 SHA 与对象规范指纹分别记录、不互相替代）。若 P1 入口为内存对象，则本阶段保存的是**该对象快照的确定性序列化字节**，不得对外表述为"保存了原始 JSON 文件字节"；材料或批次变化 → 旧决定不可复用（校验失败并停）。
- **停止点**：Gate 1 结构/质量问题未解决、Gate 2 关键隔离问题未清零、或任一指纹不符 → 不放行；不得用人工 APPROVE 掩盖结构/质量阻断。
- **最小正负向验收**：正向——真实决定在指纹一致的批次上被接受并可读回；负向——错批次/错指纹/材料变化/重复事件/模拟身份冒充/未解决阻断/不完整凭证各一例被拒；确认模拟记录**未**被当作真实凭证。

### P3 —— 真实人类独立初判（新建，独立于 AI）

- **前提**：P2 通过；D3 决定的粒度已定。
- **拟新增组件**：真实独立初判的提交与保存（按 D3：批次必填 + 可选逐条备注，或逐线索提交）；与事实底稿的指纹绑定。
- **输入/输出/绑定不变量**：初判内容仅来自人类输入（允许"暂不能判断，需要补充证据"+ 原因）；**零条线索仍须有初判，不得自动形成"无问题"**；初判保存前界面上不出现 AI 候选结论/等级/预填判断。
- **停止点**：无初判、初判与事实底稿指纹不符、或试图由程序代填 → 停止。
- **最小正负向验收**：正向——批次级"暂不能判断 + 原因"可保存并读回；负向——预填/代填、零条线索自动结论、初判前展示 AI 候选均被拒或被禁止。

### P4 —— 接入计算链（端到端，仍限合成数据）

- **前提**：P1—P3 均通过；开发态链路保持只读对照。
- **拟新增组件**：真实模式下的端到端顺序接线，**接线止于"真实初判保存"**（事实底稿 → 真实初判保存 → 人类在系统外的最终判断）。**本阶段不新增终判组件、不新增终判保存实现**：终判及其保存、AI 建议均属**另行明确范围**，不因 D2（真实决策保存模式许可）而获得授权。
- **输入/输出/绑定不变量**：每个产物登记本批代码/规则/配置/契约版本与输入指纹；`next_step_allowed` 一类默认值**不得**解锁任何真实动作。
- **停止点**：AI 未开放状态必须保持；任何需要 AI 或需要终判组件的步骤缺失即停在人类侧（不得用候选阶段替它们补齐）。
- **最小正负向验收**：正向——受控样本上走完人类决定与真实初判保存部分；负向——试图在没有真实初判记录时调用 AI、试图以 P4 接线代替终判组件、或在材料变化后复用旧决定 → 拒绝。

### P5 —— 后置 AI（**不在本方案授权范围**）

- **前提**：P1—P4 通过 **且** 另有**单独任务卡与单独授权**（模型、联网、隐私、成本、边界均须另行明确）。
- **绑定不变量**：AI 只能读取已保存的人类初判与事实底稿，输出一律标注为 **AI 辅助建议**；不得覆盖或改写人类判断。
- **停止点**：真实人类初判组件未完成、独立初判未保存、或缺少单独授权 → AI 继续不可用（**当前状态**）。
- **说明**：本卡**不是**后置 AI 任务，也不得被当作对 AI 的授权。

## 2. 跨阶段绑定与拒绝条件（不变量）

**必须绑定**（任一项不符即拒绝，不使用默认值）：

1. **批次**：决定/初判记录必须声明并匹配本批次标识（原字符串精确比较，不做大小写或数字归一化）。
2. **材料指纹（两类分列登记）**：绑定**提交时**核验的材料指纹，并**分别登记**（a）确切原始字节的**文件 SHA-256** 与（b）解析对象的**规范 JSON 指纹**；两类值不得互相替代，任一不符即拒绝，材料变化后旧决定失效。
3. **契约版本**：登记所采用的正式契约版本与指纹。
4. **身份来源**：提交人**显式声明**（本地可追溯），并明确声明其非强认证性质。
5. **时间与原因／决定说明**：均为**人类明确提供**并按其原文保存（程序不生成、不推断）；"暂不能判断"必须写明原因。此项对应候选契约 §3 的五项既有记录要素。

**输入保真口径（跨阶段一致）**：本方案各阶段在**内存对象**入口下只承诺"按原文保存人类字符串字段 + 接收到的对象快照"，**不承诺**保存原始 JSON 文件的排版/换行/BOM 字节；若将来改为**文件输入并要求原始保真**，须另存该次确切文件字节/文件 SHA 并与对象规范指纹分别绑定（另行设计与授权，非本轮范围）。

**统一拒绝清单**：缺决定 / 错批次 / 错指纹 / 材料已变化 / 重复事件 / 模拟身份冒充 / 未解决质量阻断 / 失败现场 / 不完整凭证 / 未生效契约版本 / 运行版本不一致。

**失败现场策略（保留）**：失败只在新输出目录留诊断，不修改源材料、不改写历史、不重试覆盖、不清理半写输出；诊断自身失败时如实保留原异常。
