# 决策记录：数据投放指引与"一键对账"启动器

记录编号：`DSH-SCOPE-20261017-07`。日期：2026-10-18。记录人：DSH Architect/Reviewer。依据人类要求：能看到各类原始数据应放到哪个文件夹；数据收集完后点一个按钮自动完成机器对账并直出 HTML 到某文件夹。

## 1. 决定

**D-IO-1 数据投放指引与目录骨架。** 新增 `data/inbox/` 模板：按输入类型分目录（业务台账、凭证附件、银行流水、总账账套），每个目录放 `_放入说明.md`（文件清单、格式、必填字段、命名、示例、校验命令）；生成 `intake_status.html` 与 `intake_manifest.json`，逐项显示"已提供/缺失/格式待校验"，只读扫描、不复制/不改原始数据。

**D-IO-2 "一键对账"用本机双击启动器实现，不用网页按钮直接起进程。** 静态 HTML 在浏览器里无法启动 Python/写文件（无服务器）；可靠做法是双击根目录的 `一键对账.cmd`（或 `run_all.ps1`），由 `scripts/run_all.py` 顺序执行：契约校验（task043 + GL）→ 演示链 → 证据链索引 → GL 六类核对 → 站点 → Excel → 可选审阅合并，输出到新目录 `outputs/<run_id>/`，最后打开 `index.html`。

**D-IO-3 每次运行新目录、只读输入、失败即停。** 启动器不覆盖既有运行目录；输入根只读（哈希漂移即拒绝）；任一步失败写 `run_summary.json`（步骤、退出码、错误字段）并以非零退出；不在页面里伪造成功。

**D-IO-4 不在本轮做"浏览器内按钮 + 本地服务"。** 如人类坚持网页按钮，需新增 localhost 服务模式（端口、无认证、只读、仅本机）与新的安全边界，另卡评估；本轮先交付双击启动器。

## 2. 边界

全部合成数据；启动器只做机器核对与出页，不构成审计结论、不做 AI/终判、不采集人类结论；不联网；`real_approval=null`、真实初判未保存、0008、`next/AI=false`。看板不变，`done` 由人类办理。
