## D2 —— 是否允许建设"真实人工决策保存"模式

**待决定问题**
是否允许在**现有合成数据项目内**建设一个"真实人工决策保存"模式：由主理人本人对合成数据**明确提交** Gate 决定与独立初判，由程序校验并按**原文**保存与可追溯记录；现有开发模拟模式**保留**、互不覆盖。

**建议及理由（建议，不是决定）**
建议**允许**在如下范围内建设：范围仅限"本人对合成数据提交 Gate1/Gate2 决定与独立初判的保存与校验"；接受**能力限制**——本地显式身份声明 + 材料/批次指纹绑定 + 可追溯记录，**不宣称**强身份认证、防同权限恶意篡改、不可篡改存储或独立审计保证。同时接受**口径限制**：材料指纹须**分别登记**"确切原始字节的文件 SHA-256"与"约定 canonical JSON 的规范对象指纹"，两者不互相替代；若入口为内存提交对象，则按原文保存人类字符串字段与接收到的对象快照，**不等于**保存了原始 JSON 文件的排版/换行/BOM 字节（详见接入方案 P1 与 §2）。理由：这是把已有行为边界落到可保存、可复核形态的最小一步，且不触碰真实业务数据。若需要强认证，属**另一个待定范围**，本卡不承诺已解决，也不在本卡内设计。

**接受后的实施范围**
仅授权**实施范围**：设计并实现"真实人工决策"的保存/校验组件（纯核心优先）、显式声明与指纹绑定格式、拒绝条件与失败现场策略。**不含**：真实批次批准、真实数据接入、AI 开放、终判及其保存组件、正式契约生效（D1 独立）、任何批次 APPROVE。

**暂缓时的停止点**
保持仅模拟模式；真实 Gate 决定与独立初判仍无处保存；不得以"聊过""先做着"为由先行实施，也不得把模拟记录改写或追认为真实记录。

**当前决定**：`null`（未作出）。**此许可只是实施范围授权，不是任何批次的 APPROVE。**

## D3 —— 初判提交粒度

**待决定问题**
人类独立初判按什么粒度提交与保存：
- **方案 A（建议）**：沿用**批次必填**初判 + 原因，允许对单条线索附加备注（备注可选、逐条记录）。
- **方案 B**：要求**逐线索独立提交**初判（每条线索各自成文、独立绑定）。

**建议及理由（建议，不是决定）**
建议**方案 A**：它与现有行为边界一致（"暂不能判断，需要补充证据"是有效初判；初判前只展示确定性事实），且不强制人类在信息不足时先作确定判断。方案 A 下"零条线索"仍须有批次级初判，**不得**自动形成"无问题"结论；"暂不能判断"仍须写明原因。方案 B 的代价是：零条线索场景无对象可提交，需额外规则；逐条提交还会放大"就每条先给个结论"的压力。两方案都**不**要求人类先作确定判断，也都不改变"初判前不展示 AI 候选结论/等级/预填判断"。

**接受后的实施范围**
按所选粒度确定初判记录结构（批次级 + 可选逐条备注，或逐线索记录）、绑定字段（批次、当时材料指纹、提交人显式声明、时间、原因）与校验/拒绝规则；本卡不实施。

**暂缓时的停止点**
不实现任何初判保存组件；维持"真实人类独立初判未保存"的现状，后续 AI 保持未开放。

**当前决定**：`null`（未作出）。主理人可选择 A、B 或第三种粒度，也可暂不选择。
