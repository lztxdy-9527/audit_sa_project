# 决策记录：四相符范围（账账 / 账表 / 账证 / 账实）与输入契约原则

记录编号：`DSH-SCOPE-20261017-02`。日期：2026-10-17（Asia/Singapore）。记录人：DSH Architect/Reviewer。依据：人类在本会话中的直接指示（原文见 §1）。本记录不修改正式契约，不批准任何真实批次、真实数据、强认证、OCR/AI 或审计结论。

## 1. 人类授权原文

> 账、表、凭证和银行数据都按照你建议的范围来，但我们优先实现凭证的账证相符和银行数据的账实相符这两个功能，现在可以开始拟定任务卡。

前置确认：人类已同意"不做数据清洗、不做 OCR、不做银行对账单格式适配；只处理已获取的规整数据"（见 `DSH-SCOPE-20261017-01` 与本记录 §3）。

## 2. 四个对象的口径（本项目定义）

| 对象 | 定义 | 本项目输入 |
| --- | --- | --- |
| 账 | 应付明细账、付款/退款主表、分摊/核销表（辅助账口径）；总账/科目余额表为后续输入 | 现有固定批次四表 + 后续报表输入 |
| 表 | 科目余额表/试算平衡表、应付账龄表 | 后续新增（本轮不做账表） |
| 证 | 原始凭证的**结构化字段**：发票、合同、银行回单、付款申请/审批单、入库/验收单 | 本轮新增合成凭证数据 |
| 实 | 银行流水交易级数据（可加报表层余额） | 本轮新增合成银行流水 |

## 3. 明确不做（不授权、不承诺）

1. **数据清洗**：不解析、不纠错、不补全、不猜测来源格式；格式适配在外部完成。
2. **OCR / 影像**：不处理扫描件、PDF 影像、发票图片。
3. **银行对账单格式适配**：不承诺适配未知银行格式，只接受符合输入契约的结构化流水。
4. **外部查验**：发票真伪查验、税局平台、回单验真。
5. **函证/盘点**：往来函证、存货/资产盘点、现金盘点。
6. **无索引的模糊匹配**：账证匹配以输入提供的"凭证—账务关联索引"为基础；按金额/日期/对方猜测关联不做。
7. **人类核对结论**：本轮不采集、不虚构核对结论字段；程序只输出证据与差异，人类结论留空，另行授权后再做（沿用既有"人类字段不得编造"纪律）。

## 4. 相符的层级（本轮只做 L1）

- **L1 字段级核对（做）**：单号、金额、税额、日期、对方、期间、结算状态等字段与账务记录一致；差异分类与未匹配清单；抽样底稿中的程序证据。
- **L2 原件目视（不做）**：看发票/回单原件、签章、影像。
- **L3 外部查验（不做）**：发票查验、银行回单验真、第三方确权。

对外表述必须写"字段级核对，未查看影像、未做外部查验、不证明凭证真实"。

## 5. 输入契约原则

1. 每类输入（账/表/证/银）有固定 schema、单位（整数分）、币种、期间、ID 原字符串。
2. 每个输入文件带哈希；不合契约**整批拒收**并记录拒收原因，不修、不补、不猜。
3. 输入版本与哈希进入登记；后续核对结果绑定"当时输入版本"。
4. 合成数据本轮新增，挂在既有固定批次 `batch_normal` 的同一业务实体/期间下（澄明商贸有限公司、CNY、2026-09、截至 2026-09-30）。

## 6. 优先级与卡

1. **TASK-043**：输入契约 v1 + 合成输入扩展（凭证/银行/报表占位）+ 契约校验与整批拒收 + 输入登记（哈希/版本）。
2. **TASK-044**：账证相符 L1（发票/合同/回单/审批/入库 ↔ 应付/付款/退款）+ 差异分类 + 未匹配清单 + 抽样底稿（程序状态 vs 人类结论分列）。
3. **TASK-045**：账实相符（银行流水交易级 ↔ 付款/退款）+ 未达账项/重复/金额日期对方差异 + 底稿。
4. 后续（另行授权）：账账/账表（科目余额表/试算平衡表/账龄表）、演示集成、AI 只读建议、终判。
