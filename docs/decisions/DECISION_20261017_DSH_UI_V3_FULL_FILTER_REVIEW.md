# 决策记录：UI v3——全量清单与筛选、内嵌脚本约束、网页审阅、备份与版本纪律

记录编号：`DSH-SCOPE-20261017-05`。日期：2026-10-17（Asia/Singapore）。记录人：DSH Architect/Reviewer。依据：人类在本会话中的直接指示（原文见 §1）。

## 1. 人类授权原文（摘要）

> 内嵌脚本交互有什么坏处？我认为它更方便；我希望清单范围走全量；审阅记录确实不能直接走网页填写吗？…网页填完自动生成审阅excel感觉更方便；我认为每阶段对原始数据进行备份是对的，但是我想知道数据备份在什么情况下进行？如果我每操作一次都要备份一次会不会存储不够用？

## 2. 决定

**D-UI3-1 采用内嵌脚本，但限定用途。** 允许 HTML 内嵌 `script`，**只用于筛选与审阅表单**；数据必须**全部先渲染进 HTML**（脚本关闭时仍能看到全部内容）；禁止网络请求、`eval`、外部资源、写文件；脚本不得修改任何业务数值或证据字段；打印样式固定输出**全量视图**并在页脚注明"打印为全量，筛选仅屏幕生效"。

**D-UI3-2 全量清单。** 索引与页面必须包含**全部**台账行、凭证、原表行与事项，每条带状态（已核对一致 / 存在差异 / 未取得 / 未涉及 / 待审阅），支持 `全部 / 仅异常 / 仅合规 / 待审阅` 筛选；Excel 加自动筛选。

**D-UI3-3 网页审阅。** 审阅在页面内填写（状态、审计问题描述、建议处理、审阅人、审阅日期）；浏览器只保存**草稿**（localStorage），不作为证据；点击"导出审阅记录"下载 JSON/CSV；由命令校验并生成**《审阅记录.xlsx》**、把审阅徽标与问题合并回站点与底稿。网页本身不写证据目录。

**D-UI3-4 备份与版本纪律（回答存储顾虑）。** 不按"每次操作"复制原始数据：
1. **源文件在接收时复制一次**（已有 `data/batches/<批次>/source/input.xlsx`），之后只读；
2. 生成时只记录源哈希并检查是否漂移，**不复制源**；漂移则拒绝生成，要求走新批次；
3. 每阶段证据（Gate 决定、初判、审阅记录）本身就是小文件，天然留存；
4. 每次生成的索引/站点/底稿是**新目录的小文件**（本机样本每次约 0.1–1.5 MB，200 条事项实测），不是整批复制；
5. 里程碑（验收通过/交付前）可把运行根**压缩归档一份**到外部盘，项目内不删除旧证据。
   量级：样本批次源 7 KB；100 次生成约 150 MB；真实大批次只在接收时复制一次，不会因每次操作翻倍。

## 3. 边界

`real_approval=null`、真实初判未保存、0008、`next_step_allowed=false`、`ai_enabled=false`；合成数据；UI 只读展示与审阅记录，不得覆盖机器证据；审阅记录属人类输入，需记录审阅人/日期与对应资料版本；不接影像/OCR、不做外部查验、不采集终判。看板不变，`done` 由人类办理。
