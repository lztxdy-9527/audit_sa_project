数据怎么走：六个阶段

1接收与契约校验
  • 把 Excel 四张表、凭证附件、银行流水、总账账套放进约定目录；
  • 程序只读扫描，检查SHA-256 哈希、 清单、 整数分、字段闭合、借贷平衡；
  • 任何不合规 → 整包退回，不修数据、不猜。
2两道人工闸门（演示为合成批准）
  • Gate1：确认“可以开始处理这一批”；Gate2：确认“可以出结果”；
  • 真实批准字段始终为 null；演示里的批准是合成夹具，不是真人审批；
  • 每个决定都有回执与指纹。
3标准化与 SQLite
  • 把 Excel 每一格转成统一格式，并记住“来自第几行、第几列、原值是什么”（标准化）；
  • 装入本地 SQLite，用 SQL 规则 R01–R04 找线索；
  • 再用另一套代码独立复算，防止“查询写错”。
4事实底稿与人类初判
  • 把线索、金额、来源单元格整理成事实底稿；
  • 审计人员填写初判；程序保存为六文件 + 三封装，并绑定当时材料指纹；
  • 程序不替人写结论；真实初判未保存。
5账证 / 账实 / GL 借贷核对
  • 账证相符（字段级 L1）：金额、日期、对象、方向、状态；缺失/多余单独列；
  • 账实相符（银行）：按参考号/索引匹配，期间合计，未达账项；
  • GL 六类核对：凭证平衡、试算平衡、账证、账账、账表、账实（+附件）。
6呈现：站点、Excel、审阅、一键入口
  • 生成静态 HTML 站点：问题清单、全量清单、筛选、下钻、GL 页面；
  • 生成 Excel 底稿：科目余额表、记账凭证、总账、明细账、账表核对、银行调节；
  • 网页审阅；
  • 双击 一键对账.cmd 顺序跑完七步，输出 outputs\<run_id>\index.html。

四相符与借贷核对：用这份样本讲清楚

业务链条（本样本）

供应商 S001 → 应付单 AP01 5,000.00 → 发票/合同/入库 → 付款 P01 5,000.00、P02 5,000.00 → 分摊 A01/A02 核销到 AP01 → 退款 R01 1,000.00（对应 P02）→ 分摊 AR01 冲回 AP01。

净付款 = 5,000 + 5,000 − 1,000 = 9,000.00；应付 5,000.00；超额 4,000.00（R02 线索）。

借贷口径（GL v1）

记-001 借 库存 5,000 / 贷 应付 5,000；记-002、记-003 借 应付 10,000 / 贷 银行 10,000；记-004 借 银行 1,000 / 贷 应付 1,000。

应付余额 = 贷 6,000 − 借 10,000 = 借方 4,000（多付/预付，报表重分类为预付 4,000）。试算：借 20,000 = 贷 20,000。

一句话：业务勾稽回答“这笔钱为什么多付”；借贷核对回答“账上记的对不对、借贷平不平”。两者不能互相替代。

证据怎么留：为什么它“可信”

哈希指纹

每个文件记录 SHA-256；改一个字节就对不上，能发现“偷换”。

接受基线

每次验收通过，把全项目文件的指纹存一份；下次扫描与它逐项对比。

保护扫描

一次全树扫描，确认“只改了允许改的文件”，新增逐路径登记。

只读输入

原始 Excel、凭证、流水、GL 包只读；程序只写新目录。

确定性输出

同样输入跑两次，页面/报告字节相同；不写时间戳、不用随机数。

旧证据保留

每次运行新目录，不覆盖、不删除历史证据。

技术词人话版

下表每个词都有“人话解释”；正文里带虚线下划线的词，鼠标悬停也会弹出解释。

技术词人话解释
哈希 / SHA-256给文件算一个“数字指纹”，用来发现文件被改过。
清单 / Manifest一张收货单，列出每个文件的大小与指纹，防止漏交或偷换。
接受基线上次验收通过时的“全项目指纹快照”，这次和它对比。
保护扫描一次全树对照，确认没人动过不该动的文件。
整数分钱用“分”存成整数，避免 0.01 的误差。
标准化把原始表格转成统一格式，同时记住每个数字来自哪一格。
SQLite一个本地数据库文件，像“程序版 Excel”。
SQL 筛查用查询语句找“净付款超过应付”这类线索。
独立复算不只信一次查询，再用另一种算法算一遍对账。
事实底稿把线索、金额、原表行号列号整理成可核对的底稿。
Gate1 / Gate2两道“人工批准闸门”，演示里是合成批准。
账证相符账上的数，和发票、合同、入库、审批、回单对得上。
账实相符账上的付款/退款，和银行流水逐笔对上。
L1 字段级只比字段，不看发票影像，也不打电话给银行。
未达账项银行和企业的账“时间差”，需要编余额调节表。
借贷记账法每笔业务至少一借一贷，借贷金额必须相等。
会计分录一笔业务在账上“借什么、贷什么”的记录。
试算平衡所有科目借方合计 = 贷方合计，检查记账有没有算错。
总账 / 明细账总账按科目汇总，明细账按供应商/对象逐笔记。
科目余额表每个科目期初、本期发生、期末余额的汇总表。
三栏式借、贷、余额三栏的账页格式。
重分类应付出现借方余额，报表里调到“预付账款”。
账账 / 账表总账与明细账对、账簿与报表对。
附件索引凭证和原始单据的对应关系表。
幂等重复跑不会重复写、不会覆盖旧结果。
JSON一种文本格式，像带标签的清单，程序好读。
CSV逗号分隔的表格文本，Excel 能打开。
localStorage浏览器本地的小抽屉，只存草稿，不是证据。
静态站点不用服务器，双击 HTML 就能看。
超链接定位Excel 里点金额/凭证号，跳到对应原表行。
自动筛选Excel 表头下拉筛选，按状态/审阅状态过滤。
OCR把图片里的字认出来；本项目没做。
函证发函给银行/供应商确认余额；本项目没做。
监盘到仓库数实物；本项目没做。

边界：它不做什么

不做：数据清洗、银行对账单版式适配、发票/回单影像与 OCR、外部查验、函证、监盘、期后付款、截止测试、账龄分析、关联方/舞弊专项、AI 建议、人类终判。

不承诺：凭证/流水真实、发票真伪、批次批准、身份认证、审计结论。真实批准 null、真实初判未保存、next_step_allowed=false、ai_enabled=false。

适用：已规整的合成数据演示；换真实数据需另行授权、脱敏、输入映射与新卡。
